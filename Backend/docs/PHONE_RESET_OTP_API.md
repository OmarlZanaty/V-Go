# Phone password-reset OTP over the Collector SIM

Firebase Phone Auth sends no SMS on the Spark plan, so forgot-password OTPs are generated by the
backend and sent as plain SMS by the V-Go Collector app (the company phone that already relays
wallet SMS). The same SIM is used, chosen by the collector's "OTP SIM" setting (default SMS SIM).

## Flow

1. App → `POST /api/Auth/phone-reset/request {phone}`; the backend creates a 6-digit code and
   queues one SMS in `SmsOutbox`.
2. Collector polls `GET /api/Collector/outbox` every ~4 s, sends each SMS with `SmsManager`, and
   reports `POST /api/Collector/outbox/{id}/result`.
3. App → `POST /api/Auth/phone-reset/verify {phone, code}` → `resetToken`.
4. App → `POST /api/Auth/phone-reset-password {resetToken, newPassword}` (the existing endpoint;
   the legacy `idToken` (Firebase) path stays working for old app versions).

All phones are normalized with `AuthService.NormalizePhone` (the same form as `User.PhoneNumber`).
JSON is camelCase. Errors use `{ isSuccess:false, message:"<Arabic>", code:"<CODE>" }`.

## App endpoints (anonymous, `[EnableRateLimiting("auth")]`)

### POST /api/Auth/phone-reset/request
Body `{ "phone": "01012345678" }`

| Case | Status | code | message |
|---|---|---|---|
| queued | 200 | — | `تم إرسال رمز التحقق` + `data: { expiresInSeconds: 300, cooldownSeconds: 60 }` |
| no account with this phone | 404 | `NO_ACCOUNT` | `لا يوجد حساب بهذا الرقم` |
| a code was requested < 60 s ago | 429 | `COOLDOWN` | `انتظر قليلًا قبل طلب رمز جديد` + `data: { cooldownSeconds: <remaining> }` |
| > 5 requests for this phone in the last hour | 429 | `TOO_MANY` | `محاولات كثيرة، حاول بعد ساعة` |
| > 300 OTP SMS queued today (global SIM guard) | 503 | `SMS_DAILY_LIMIT` | `خدمة الرسائل مشغولة حاليًا، حاول لاحقًا أو تواصل مع الدعم` |
| no active collector device with a heartbeat in the last 3 min | 503 | `SMS_OFFLINE` | `خدمة الرسائل غير متاحة حاليًا، حاول بعد قليل أو تواصل مع الدعم` |

A new request invalidates the phone's previous unused codes. SMS body (one UCS-2 segment, ≤ 70 chars):
`V.Go: كود تغيير كلمة السر {code}\nصالح 5 دقائق ولا تشاركه مع أحد`

### POST /api/Auth/phone-reset/verify
Body `{ "phone": "01012345678", "code": "123456" }`

| Case | Status | code | message |
|---|---|---|---|
| correct | 200 | — | `data: { resetToken: "<opaque>", expiresInSeconds: 600 }` |
| wrong code | 400 | `INVALID_CODE` | `رمز التحقق غير صحيح` (+ `data: { attemptsLeft }`) |
| expired / no active code | 400 | `CODE_EXPIRED` | `انتهت صلاحية الرمز، اطلب رمزًا جديدًا` |
| 5 wrong attempts on this code | 429 | `TOO_MANY_ATTEMPTS` | `محاولات كثيرة، اطلب رمزًا جديدًا` (code is burned) |

Compare codes in constant time. The code is single-use and is consumed on success.

### POST /api/Auth/phone-reset-password (existing)
`PhoneResetPasswordDTO` gains `string? ResetToken`. If `ResetToken` is set, it is validated
(hash match, unexpired, unused), consumed, and the password of the code's user is reset. Otherwise
the existing Firebase `IdToken` path runs unchanged. Invalid/expired token → 401
`انتهت صلاحية الجلسة، أعد المحاولة`.

## Collector endpoints (`X-Device-Key`, same auth as `/heartbeat`)

### GET /api/Collector/outbox?max=5
Atomically claims up to `max` (≤ 10) messages that are `Pending`, or `Claimed` with a lease older
than 60 s, and not past `ExpiresAt`. Sets `Status=Claimed, ClaimedByDeviceId, ClaimedAt, Attempts++`.
A message with `Attempts >= 3` or past `ExpiresAt` becomes `Expired` and is not returned.
→ `200 { isSuccess:true, data:[ { id:"<guid>", to:"+201012345678", body:"..." } ] }`

### POST /api/Collector/outbox/{id}/result
Body `{ "sent": true, "error": null }` → `Sent` (`SentAt`) or back to `Pending` with `Error`
(retried until `Attempts >= 3`, then `Failed`). Only the claiming device may report. → `200`.

## Data (one EF migration `Phone_Reset_Otp`)

- `PhoneOtps`: `Id` Guid, `UserId`, `Phone`(32), `Purpose`(20, "reset"), `CodeHash`(64),
  `CreatedAt`, `ExpiresAt`, `Attempts` int, `ConsumedAt?`, `ResetTokenHash?`(64),
  `ResetTokenExpiresAt?`, `ResetTokenUsedAt?`. Index (`Phone`,`CreatedAt`).
- `SmsOutbox`: `Id` Guid, `To`(32), `Body`(320), `Purpose`(20), `Status`(16: Pending/Claimed/Sent/
  Failed/Expired), `Attempts` int, `ClaimedByDeviceId?`, `ClaimedAt?`, `SentAt?`, `Error?`(300),
  `CreatedAt`, `ExpiresAt`. Index (`Status`,`CreatedAt`).

Hashes are HMAC-SHA256 (hex) keyed with an app secret (reuse an existing server secret already in
config; never log codes or tokens). Times use the project's existing clock convention.
